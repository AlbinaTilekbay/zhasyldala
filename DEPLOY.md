# Деплой на Railway (свой домен, в интернете)

Это пошаговая инструкция «с нуля»: у вас пока нет GitHub-репозитория, и
проект нужно и залить в интернет, и повесить на свой домен.

**Важное ограничение:** я не могу сам зайти в ваш аккаунт Railway/GitHub
или ввести туда пароли/ключи — это правило безопасности, которое я не
обхожу ни при каких обстоятельствах. Всё, что ниже помечено как «вы
делаете» — занимает пару кликов и делается один раз. Дальше, после того
как GitHub подключён к Railway, каждое обновление кода (`git push`)
разворачивается само, без ручных действий.

Что уже подготовлено в проекте под этот деплой (я это сделал за вас):

- `Dockerfile.railway` — собирает React-фронтенд и Django-бэкенд в один
  образ: один процесс (gunicorn) отдаёт и сайт, и API, и админку.
- `railway.json` — говорит Railway использовать именно этот Dockerfile.
- `backend/config/settings.py` — теперь понимает `DATABASE_URL` (так
  Railway передаёт данные для подключения к Postgres) и умеет отдавать
  собранный фронтенд с корня сайта.
- `backend/config/urls.py` — добавлен fallback-роут, чтобы прямые ссылки
  на `/dashboard`, `/scan` и т.д. открывались корректно (это одностраничное
  React-приложение).

## 0. Что нужно иметь заранее

- Аккаунт GitHub (бесплатно, github.com).
- Аккаунт Railway (бесплатно, railway.app — можно войти через GitHub).
- Домен, который вы хотите привязать (купленный на любом регистраторе —
  Namecheap, GoDaddy, reg.kz и т.д.). Без домена тоже можно — Railway сам
  выдаёт бесплатный поддомен вида `zhasyldala-production.up.railway.app`.

## 1. Залить проект в GitHub

В терминале на Mac, из папки проекта (там, где лежат `backend/` и
`frontend/`):

```bash
cd путь/до/zhasyldala
git init
git add .
git commit -m "ZhasylDala: initial commit"
```

Дальше на github.com: **New repository** → дайте имя (например
`zhasyldala`) → **не** отмечайте «Add README»/«.gitignore»/«license» (репо
должно быть пустым) → **Create repository**. GitHub покажет вам ссылку
вида `https://github.com/ваш-логин/zhasyldala.git` — скопируйте её и
выполните:

```bash
git branch -M main
git remote add origin https://github.com/ваш-логин/zhasyldala.git
git push -u origin main
```

(`.env` и `db.sqlite3` уже в `.gitignore` — секреты и локальная база в
репозиторий не попадут.)

## 2. Создать проект в Railway

1. railway.app → **Login with GitHub** → **New Project** → **Deploy from
   GitHub repo** → выбрать `zhasyldala`.
2. Railway увидит закоммиченные `railway.json`/`Dockerfile.railway` и
   соберёт проект как единый сервис — ничего дополнительно настраивать не
   нужно. Первая сборка займёт минут 5–10 (устанавливается PyTorch).

## 3. Добавить базу данных Postgres

В том же Railway-проекте: **+ New** → **Database** → **Add PostgreSQL**.

Затем откройте ваш web-сервис → вкладка **Variables** → **New Variable** →
имя `DATABASE_URL`, а в значении начните печатать `${{` — Railway
подскажет `${{Postgres.DATABASE_URL}}`. Это ссылка на переменную из
Postgres-сервиса: подключение настроится само и переживёт пересоздание
пароля.

## 4. Переменные окружения веб-сервиса

Там же, во вкладке **Variables**, добавьте:

```
DJANGO_SECRET_KEY=<случайная строка>
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=.up.railway.app
CORS_ALLOWED_ORIGINS=https://ваш-поддомен.up.railway.app
CSRF_TRUSTED_ORIGINS=https://ваш-поддомен.up.railway.app
CELERY_TASK_ALWAYS_EAGER=True
```

Важно: `DJANGO_ALLOWED_HOSTS` — это точка в начале (`.up.railway.app`), а
**не** звёздочка (`*.up.railway.app`). Django понимает точку в начале
как «любой поддомен», а звёздочку — никак, и такой домен просто не
пройдёт проверку с непонятной ошибкой `DisallowedHost`.

Основной способ диагностики — OpenAI (фото отправляется напрямую в
OpenAI, она сама распознаёт растение и болезнь и пишет карточки с
рекомендациями). Без этого ключа приложение всё равно работает — просто
переходит на офлайн-модель (PlantVillage), см. README, раздел «Primary
diagnosis engine: OPENAI_API_KEY»:

```
OPENAI_API_KEY=<ключ с platform.openai.com/api-keys>
```

`DJANGO_SECRET_KEY` сгенерируйте локально одной командой и вставьте
результат:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(50))"
```

`CELERY_TASK_ALWAYS_EAGER=True` — потому что в этой упрощённой схеме нет
отдельного Redis/worker (как обсуждали, выбрали «один сервис» ради
простоты и цены); фоновые задачи (обработка видео, обучение модели)
выполняются синхронно прямо во время запроса. При текущих объёмах это
нормально; если станет тесно — можно добавить Redis-плагин и worker-сервис
позже, ничего не переписывая с нуля.

Поддомен вида `zhasyldala-production.up.railway.app` Railway выдаёт сразу
после первого деплоя — посмотрите его в **Settings → Networking** сервиса
и подставьте в
переменные выше вместо `ваш-поддомен`.

## 5. Постоянное хранилище для фото и обученной модели

**Это важный шаг** — без него каждый передеплой будет стирать все
загруженные фото и обученную модель (файловая система контейнера
пересоздаётся с нуля при каждой сборке).

Сервис → **Settings** → **Volumes** → **Add Volume** → путь монтирования:
`/app/media`.

## 6. Домен

### Без своего домена
Ничего делать не нужно — сайт уже доступен по адресу
`https://ваш-поддомен.up.railway.app`.

### Со своим доменом
Сервис → **Settings** → **Networking** → **Custom Domain** → введите ваш
домен (например `zhasyldala.kz` или `app.zhasyldala.kz`) → Railway покажет
CNAME-запись вида `xxxx.up.railway.app`.

Дальше — у вашего регистратора домена (там, где покупали домен), в
разделе DNS: добавьте запись типа **CNAME**, имя — ваш поддомен (или `@`
для корневого домена, если регистратор это поддерживает), значение — то,
что показал Railway. Подтверждение и HTTPS-сертификат обычно занимают от
нескольких минут до пары часов.

После этого обновите переменные из шага 4 — замените
`ваш-поддомен.up.railway.app` на настоящий домен в `DJANGO_ALLOWED_HOSTS`,
`CORS_ALLOWED_ORIGINS`, `CSRF_TRUSTED_ORIGINS` (можно перечислить оба через
запятую, чтобы старый Railway-поддомен тоже продолжал работать).

## 7. Обучить модель на сервере (один раз)

`migrate` и `seed_data` (крупы/болезни/советы) запускаются автоматически
при каждом старте контейнера — база сразу готова. А вот
`bootstrap_plantvillage` (скачивание датасета + обучение) — разовая
операция, её нужно запустить вручную один раз после первого успешного
деплоя.

Установите Railway CLI на Mac и подключитесь к проекту:

```bash
npm install -g @railway/cli
railway login
cd путь/до/zhasyldala
railway link          # выберите ваш проект и сервис
railway ssh           # открывает терминал ВНУТРИ работающего контейнера
```

И уже внутри этого удалённого терминала:

```bash
python manage.py bootstrap_plantvillage
```

Так скачивание и обучение идут на сервере (где есть интернет и уже
установлен PyTorch), а результат сразу сохраняется в примонтированный том
из шага 5 — переживёт следующие деплои.

## 8. Дальнейшие изменения кода

Когда я меняю что-то в коде дальше по ходу работы, порядок такой же, как
и был:

```bash
# скопировать присланные мной файлы поверх старых в вашей папке проекта
git add .
git commit -m "описание изменения"
git push
```

Railway сам подхватит `push` в `main` и передеплоит сайт — заходить в
Railway для этого не нужно.
